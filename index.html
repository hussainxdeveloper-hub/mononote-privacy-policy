Privacy Policy

This privacy policy applies to MonoNote and any related services operated by Hussain.

1. What Data We Collect

MonoNote is built with privacy in mind. Most of your data never leaves your device. Here is exactly what we collect and what stays local:

1.1 Data That STAYS on Your Device (We Never See This)

The following data is stored only on your device using local storage. It is never sent to us or any server unless you explicitly enable Cloud Sync (Premium feature):

  • Your notes and their content
  • Your to-do lists and items
  • Your password vault entries (stored encrypted on your device)
  • Your Safe Box photos and videos (stored in a private app folder)
  • Your reminder times and notification settings
  • Your theme and app preferences

1.2 Data We Actually Collect

We only collect the following limited data:

  • Google Account Email and Name: When you sign in with Google, we receive your email address and display name for authentication purposes only.
  • Device Information: Android device model and OS version, used only for registering your device in sync (Premium users only).
  • App Usage Events: Anonymous events like "note created" or "todo created" sent to Firebase Analytics. No note content is ever included.
  • Crash Reports: Automatic crash logs sent to Firebase Crashlytics to help us fix bugs. These contain stack traces and device state — never your personal content.
  • Subscription Status: Whether you have an active Premium subscription, managed by RevenueCat.
  • Advertising Data (Free Users Only): If you are not a Premium subscriber, Google AdMob collects device/advertising identifiers, IP address, and app interaction data to serve and measure ads. See Section 8 below for details. Premium subscribers never see ads and this data is not collected from them for advertising purposes.

1.3 Cloud Sync Data (Premium Users Only — Optional)

If you are a Premium subscriber and choose to enable Cloud Sync, your notes and encrypted password entries are synced to Supabase servers. This is entirely optional and can be disabled at any time in Settings. Password data is encrypted on your device before being sent — we never see your plaintext passwords.

1.4 Google Drive Backup (Optional)

If you use the Backup feature, your data is saved to a hidden private folder in your own Google Drive account (app data folder — not visible in your Drive). Only you can access this. We do not have access to your Google Drive files.

2. How We Collect It

  • Data you give us directly: When you sign in with Google, create notes, set reminders, or configure app settings.
  • Data collected automatically: Through third-party services like Firebase, RevenueCat, and Google AdMob, and device info APIs when you use MonoNote.

3. Local Storage

MonoNote stores most of your data locally on your device using the Hive local database. Here are the storage boxes we use:

  • notes: All your notes
  • todo_lists: All your to-do lists
  • todo_items: Individual to-do items
  • password_entries: Password vault entries (encrypted with AES-256 via HiveAesCipher)
  • safe_photos: Safe Box media metadata
  • vault_photos: Vault photos metadata

Additional preferences (theme, dark mode, biometric settings) are stored via SharedPreferences and flutter_secure_storage (for encryption keys, master password hashes, and master PIN hashes).

4. Cloud Storage (Supabase)

When you have an active premium subscription and enable sync, your data is synced to Supabase cloud servers. We use the following database tables:

  • notes: Synced notes data (content, title, timestamps, deletion status)
  • password_entries: Password vault entries with end-to-end encryption (passwords are AES-256 encrypted before being sent to the server)
  • sync_devices: Registered device information (device ID, device name, last sync timestamp)

Sync is only available to premium users and can be disabled at any time from the Settings screen.

5. Google Drive Backup

MonoNote can back up your data to Google Drive using the drive.appdata folder (hidden from your Google Drive UI, accessible only by MonoNote). Here is what gets backed up:

  • Notes backup: All notes (files: mononote_notes_backup.json and auto backup variants)
  • To-do lists backup: All to-do lists and items (files: mononote_todos_backup.json)
  • Password vault backup: Encrypted password entries (files: mononote_passwords_backup.json and auto variants)
  • Safe Box media backup: Photos and videos from Safe Box, uploaded as content-hash-named files with metadata

Backup can be performed manually or automatically (auto-backup for premium users). Previous versions (up to 3) are preserved for each backup file.

6. Encryption

MonoNote uses AES-256 encryption (CBC mode) to protect sensitive data:

  • Password Vault: The Hive box for password entries is encrypted with HiveAesCipher using a key stored in flutter_secure_storage.
  • Sync Encryption: Passwords synced to Supabase are encrypted end-to-end using AES-256-CBC with a randomly generated 16-byte IV per encryption call. The encryption key is derived from your user ID. Encrypted data is stored in the format "ivBase64:ciphertextBase64".
  • Safe Box / Vault Photos: Media files stored in the Safe Box are copied to a private app directory with a .nomedia file to prevent gallery scanning.
  • Secure Storage: Master password hashes, PIN hashes, pattern hashes, vault encryption keys, and security answer hashes are stored using flutter_secure_storage (Android EncryptedSharedPreferences).

  • Google AdMob (Privacy Policy) — Displays ads to free (non-Premium) users. Collects advertising identifiers, IP address, and app interaction data for ad delivery, personalization, analytics, and fraud prevention. See Section 8 for full details.
  • Supabase (Privacy Policy) — Cloud database for authentication and sync.
  • Firebase Analytics (Privacy Policy) — Usage analytics and event tracking.
  • Firebase Crashlytics (Privacy Policy) — Crash reporting.
  • RevenueCat (Privacy Policy) — In-app purchase and subscription management.
  • Google Sign-In (Privacy Policy) — Authentication.
  • Google Drive API — Backup and restore functionality.

8. Advertising (Google AdMob)

MonoNote is free to download and use. To support the free tier, we display ads provided by Google AdMob to non-Premium users only. Premium subscribers never see ads anywhere in the app.

8.1 What AdMob Collects

When you are shown an ad, Google Mobile Ads SDK automatically collects and shares the following, for advertising, analytics, and fraud-prevention purposes:

  • IP address — used to estimate your general (approximate) location.
  • Advertising identifiers — your Android Advertising ID and App Set ID, and any other identifiers tied to signed-in accounts on your device.
  • App interaction data — events like app launches, ad taps, and ad video views.
  • Diagnostic information — app/SDK performance data such as launch time and stability metrics.

All data collected by the Google Mobile Ads SDK is encrypted in transit using TLS.

8.2 Where Ads Appear

Ads may appear as banner ads (on the Home and To-Do screens, and on all Trash screens), interstitial ads (for example, after unlocking the Password Vault or changing your theme), and rewarded video ads (for example, when setting a reminder, opening Safe Box, or performing a manual backup/restore). We apply frequency limits so ads are not shown excessively — for example, some ad types are capped to a limited number of times per day and a minimum time between ads.

8.3 Ad Personalization Choices

You can control ad personalization and your advertising identifier directly from your device:

  • On Android, go to Settings > Google > Ads to opt out of personalized advertising or to reset your Advertising ID.
  • Opting out of ad personalization does not stop ads from appearing — it means ads you see will be less tailored to your interests.

8.4 Children and Ads

Consistent with Section 21 (Children's Privacy) below, we do not knowingly serve personalized ads to children under 13. If you are a parent or guardian with concerns about ads shown to a child using MonoNote, please contact us at hussainxdeveloper@gmail.com.

8.5 More Information

For full details on what Google's advertising products collect and how that data is used, see Google's Ads Privacy & Terms and Privacy Policy.

9. Firebase Analytics Events

MonoNote logs the following events via Firebase Analytics:

  • note_created — When you create a new note.
  • todo_created — When you create a new to-do list.
  • google_sign_in_success — When you successfully sign in with Google.
  • safebox_media_added — When you add media to the Safe Box.

No personal or sensitive content (note text, passwords, etc.) is included in these events.

10. Firebase Crashlytics

Firebase Crashlytics collects crash reports including stack traces, device state, and app version to help us fix bugs and improve stability. No personal data is intentionally collected in crash reports.

11. RevenueCat (In-App Purchases)

RevenueCat manages in-app purchases and subscription status. RevenueCat receives:

  • Your user ID (for linking purchases across devices)
  • Your subscription status (active/inactive/trial)
  • Purchase history

RevenueCat handles all payment processing. MonoNote never accesses or stores your credit card or payment details.

12. Supabase (Authentication and Cloud Sync)

Supabase provides authentication (via Google Sign-In) and cloud sync. When you sign in, Supabase stores your email and user ID. When sync is enabled, your notes, to-do lists, and password entries (encrypted) are stored on Supabase servers.

13. Google Sign-In

Google Sign-In is used for authentication, enabling cloud sync and Google Drive backup. We receive your email address and profile information when you sign in. We also request the drive.appdata scope to back up and restore your data to a private app-specific folder in Google Drive.

14. Permissions

MonoNote requests the following Android permissions:

  • com.android.vending.BILLING — Required for in-app purchases (subscriptions) via Google Play.
  • READ_MEDIA_IMAGES (Android 13+) — To import photos into the Safe Box.
  • READ_MEDIA_VIDEO (Android 13+) — To import videos into the Safe Box.
  • READ_MEDIA_AUDIO (Android 13+) — To import audio files if supported.
  • READ_MEDIA_VISUAL_USER_SELECTED (Android 14+) — To allow you to grant partial access to selected media only.
  • ACCESS_MEDIA_LOCATION — To access media location metadata if needed.
  • MANAGE_EXTERNAL_STORAGE — Required for deleting original media files from the gallery after importing them into the Safe Box.
  • POST_NOTIFICATIONS (Android 13+) — To show reminder notifications for notes and to-do lists.
  • SCHEDULE_EXACT_ALARM (Android 12+) — To schedule precise reminder notifications.
  • USE_EXACT_ALARM (Android 14+) — To schedule exact alarm times for reminders.
  • RECEIVE_BOOT_COMPLETED — To re-schedule reminders after device restart.
  • READ_EXTERNAL_STORAGE (Android 12 and below) — Legacy permission for accessing media files.
  • WRITE_EXTERNAL_STORAGE (Android 9 and below) — Legacy permission for writing media files.
  • USE_BIOMETRIC — To authenticate using fingerprint or face unlock for app lock and vault unlock.
  • USE_FINGERPRINT — Legacy biometric permission for fingerprint authentication.
  • WAKE_LOCK — To keep the device awake during background tasks (auto backup).

15. Biometric Data

MonoNote uses biometric authentication (fingerprint or face unlock) for two features:

  • App Lock: Lock the entire app behind biometric authentication.
  • Password Vault Unlock: Unlock the password vault using biometrics.

Biometric authentication is handled entirely by your device's LocalAuthentication API. MonoNote never stores, transmits, or has access to your biometric data. Only a simple on/off preference is stored locally.

16. Media and Files (Safe Box)

The Safe Box feature lets you import photos and videos into a private app directory that is not accessible by gallery apps or file managers. Here is how it works:

  • The original file is copied to a private directory within the app storage.
  • A .nomedia file prevents gallery scanning of the private directory.
  • After successful import, the original file is deleted from public storage (gallery, DCIM, etc.) using multiple deletion methods including PhotoManager API.
  • Imported media is only accessible through MonoNote when the vault is unlocked.
  • You can restore media back to your device gallery at any time.

17. Notifications

All notifications in MonoNote are local only. They are scheduled on your device using Flutter Local Notifications and are never sent to our servers or anyone else. The following notification data is stored locally:

  • Note title and content snippet (for note reminders)
  • To-do list title (for to-do reminders)
  • Scheduled reminder time (converted to timezone-aware format)

18. In-App Purchases and Subscriptions

MonoNote offers premium subscriptions with a 3-day free trial. All payment processing is handled by RevenueCat and Google Play Store:

  • MonoNote never sees, stores, or processes credit card or payment information.
  • RevenueCat receives subscription status and user ID to manage entitlements across devices.
  • You can restore previously purchased subscriptions from any device.
  • Subscriptions can be managed through Google Play Store > Subscriptions.

19. Data Retention

We keep your data for the following periods:

  • Your content (notes, to-dos, passwords, media): Kept for as long as you use MonoNote plus 12 months after account deletion, unless you ask us to delete it sooner.
  • Analytics and crash reports: Firebase Analytics keeps data for up to 24 months. Crash reports are kept for up to 90 days.
  • Advertising data: Data collected by Google AdMob (advertising ID, IP address, interaction data) is retained according to Google's own retention policies, which we do not control. See Google's Ads Privacy & Terms for details.
  • Subscription Data: Kept while your subscription is active. After cancellation, basic purchase history may be kept for legal and accounting reasons.
  • Trashed Items: Soft-deleted notes, passwords, and media are automatically purged after 7 days (free users) or 30 days (premium users).
  • Aggregated and Anonymized Data: Kept indefinitely since it no longer identifies you.

21. Children's Privacy

MonoNote is a general-purpose notes and productivity app suitable for all ages. Anyone can use it to write notes, make to-do lists, and organize their thoughts — including younger users with the guidance of a parent or guardian.

However, because MonoNote uses third-party services that collect limited anonymous data (such as Firebase Analytics, Google Sign-In, and Google AdMob for free users), we are required by law (COPPA in the US and similar laws in other regions) to set a minimum age of 13 years for independent use of the app and especially for features that involve data collection, such as Google Sign-In, Cloud Sync, viewing ads, and Premium purchases.

Here is what this means in practice:

  • Under 13: Children under 13 can use the core offline features of MonoNote (writing notes, to-do lists, using the password vault) under the supervision of a parent or guardian. The parent or guardian must agree to these Terms and the Privacy Policy on the child's behalf. Children under 13 should not sign in with Google or enable Cloud Sync.
  • 13 and above: You can use all features of MonoNote independently, including Google Sign-In, Cloud Sync, and Premium subscriptions.

We do not knowingly collect personal data from children under 13 without verifiable parental consent, and we do not knowingly serve personalized ads to children under 13. If we discover that a child under 13 has signed in and provided personal information without parental consent, we will promptly delete that data. If you are a parent or guardian and believe your child has done this, please contact us at hussainxdeveloper@gmail.com.

22. Security Measures

MonoNote uses the following security measures to protect your data:

  • AES-256 Encryption: Passwords stored in the vault are encrypted with AES-256-CBC using randomly generated IVs.
  • End-to-End Encryption for Sync: Password data synced to Supabase is encrypted on your device before transmission — the server never sees plaintext passwords.
  • Encrypted Local Storage: Hive boxes for sensitive data use HiveAesCipher encryption.
  • Flutter Secure Storage: Encryption keys, master password hashes, and PIN hashes are stored in Android EncryptedSharedPreferences.
  • Supabase Row Level Security (RLS): Database tables use RLS policies to ensure users can only access their own data.
  • Biometric Authentication: Optional biometric lock adds an extra layer of device-level security.
  • Private Media Storage: Safe Box media is stored in a private app directory invisible to gallery and file manager apps.
  • Secure File Deletion: Original media files are deleted from public storage using PhotoManager API after import to Safe Box.
